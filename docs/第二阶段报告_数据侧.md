## 3. 数据库 v1.0

### 3.1 表与主码

| 表 | 主码 | 关键约束 |
|---|---|---|
| `Product` | `product_id` | `(product_name, category)` UNIQUE；价格/预警库存非负；状态枚举 |
| `Inventory` | `inventory_id` | `product_id` UNIQUE；数量非负 |
| `InventoryLog` | `log_id` | 入库为正、销售为负；类型枚举 |
| `Member` | `member_id` | `phone` UNIQUE；积分非负 |
| `Employee` | `employee_id` | `phone`、`login_name` UNIQUE；角色枚举 |
| `Orders` | `order_id` | 会员可空；员工必填；支付/状态枚举 |
| `OrderDetail` | `detail_id` | 数量>0；单价>=0；`subtotal` 为 PERSISTED 计算列 |
| `PetService` | `service_id` | `service_name` UNIQUE；时长>0 或空 |
| `ServiceAppointment` | `appointment_id` | 服务必填；会员/员工可空；状态枚举 |

### 3.2 视图

| 视图 | 用途 |
|---|---|
| `v_order_detail` | 订单 + 明细 + 商品 + 员工 + 会员，散客显示“散客” |
| `v_order_header` | 订单头 + 会员姓名 + 员工姓名，供店员订单页 |
| `v_product_sales` | 商品销量与销售额 |
| `v_inventory_status` | 库存数量与状态（缺货/库存不足/正常） |
| `v_member_consumption` | 会员订单数与消费总额 |
| `v_service_appointment` | 预约 + 服务 + 会员 + 员工 |
| `v_employee_login` | 登录凭据，只授予 `petcare_auth` |

### 3.3 序列与索引

- 9 个 `SEQ_*`，起始 1001，DAO 用 `NEXT VALUE FOR` 生成 `CHAR` 主码；
- 订单时间、会员、员工、明细订单/商品、库存流水商品+时间、预约时间共 7 个索引；
- `SchemaVersion` 记录 `v1.0`。

### 3.4 迁移结果

- `OrderDetail.subtotal` 从普通列改为 `PERSISTED` 计算列，消除 3NF 违反和更新异常；
- `Employee` 增加 `login_name`、`password_hash`、`is_active`；
- 迁移前后 9 张表行数、5 个视图结果、订单金额完全一致；
- `regression.sql` 九组检查全部 PASS。

详细分析见 `docs/w6_规范化与迁移说明.md`。

## 4. DAO 架构

### 4.1 分层与事务

```text
页面层（B） → 业务层（B） → DAO（A） → SQL Server
```

- 事务边界在 B 的业务层：`with db.transaction("clerk") as conn:`；
- DAO 只接收 `conn`，不 commit/rollback/close；
- `Database.transaction()` 检测嵌套，嵌套直接抛 `TransactionStateError`；
- 所有 SQL 参数化；LIKE 通配符转义并 `ESCAPE '\'`；
- 动态列名只走 DAO 内部白名单。

### 4.2 模块

| 模块 | 职责 |
|---|---|
| `config.py` | 读取 `.env`，构造 auth/clerk/manager 连接串 |
| `database.py` | `read`、`auth_read`、`transaction`、`ping` |
| `errors.py` | `DAOError`、`ErrorCode`、pyodbc/SQL Server 错误翻译 |
| `ids.py` | `NEXT VALUE FOR dbo.SEQ_*`，格式化为 `CHAR` 主码 |
| `utils.py` | `cursor_scope`、分页校验、LIKE 转义、行转字典、输入校验 |
| `product_dao.py` | 商品列表/详情/创建/更新/停用/删除/类别 |
| `inventory_dao.py` | 库存查询/创建/原子调整/预警/流水 |
| `order_dao.py` | 多商品下单、订单查询、状态更新、明细 |
| `member_dao.py` | 会员搜索/详情/创建/更新/积分 |
| `employee_dao.py` | 登录凭据、员工详情/列表 |
| `report_dao.py` | 商品销售、库存状态、会员消费 |

### 4.3 统一错误

`DAOError` 只抛业务安全信息，原始 pyodbc 错误放 `detail` 供日志。主要错误码：

| 错误码 | 场景 |
|---|---|
| `VALIDATION_ERROR` | 分页、数量、类型、长度、枚举 |
| `NOT_FOUND` | 商品/订单/库存不存在 |
| `BUSINESS_RULE_VIOLATION` | 库存不足、停售商品下单 |
| `CONFLICT_UNIQUE` | 手机号、库存行、登录名重复 |
| `CONFLICT_FOREIGN_KEY` | 删除被引用商品、无效会员/员工 |
| `CONFLICT_CHECK` | CHECK 约束 |
| `FORBIDDEN` | 受限账号权限不足（229/230） |
| `DB_TIMEOUT` | 死锁/超时，`retryable=True` |
| `DB_UNAVAILABLE` | 连接失败、登录失败、库不存在 |
| `TRANSACTION_FAILED` | commit/rollback 失败或嵌套事务 |
| `INTERNAL_ERROR` | 表/列/存储过程缺失等 |

### 4.4 `cursor_scope` 的必要性

pyodbc 5.4 的 `with conn.cursor() as cur:` 在退出时会提交连接，导致测试中的 rollback 失效、测试数据写进主库。DAO 统一使用：

```python
with cursor_scope(conn) as cur:
    ...
```

`cursor_scope` 只关闭 cursor，不碰事务。这是本阶段排查出的关键兼容性问题，已在 README 和测试中记录。

## 5. 数据库账号与权限

| 账号 | 角色 | 权限 |
|---|---|---|
| `petcare_auth` | 无业务角色 | 只读 `v_employee_login` |
| `petcare_clerk` | `role_clerk` | 商品/库存/订单/会员/服务视图查询；库存更新；下单所需序列 `UPDATE` |
| `petcare_manager` | `role_manager` | 商品/库存/员工/订单/报表；全部业务序列 `UPDATE` |

关键修正：

1. v0.1 只给店员 `SELECT Inventory`，下单扣库存会失败；已补 `GRANT UPDATE ON dbo.Inventory TO role_clerk`；
2. 店员无 `Employee` 基表权限，订单页通过 `v_order_header` 取员工姓名；
3. `NEXT VALUE FOR` 需要序列对象 `UPDATE` 权限，已按角色实际使用的序列最小授予；
4. `clerk_user`/`manager_user` 是 `WITHOUT LOGIN`，只用于 `EXECUTE AS` 回归；应用使用三个真实登录账号。

## 8. 给 B 的交接说明

1. **入口**：`from dao import Database, DbConfig, ProductDAO, InventoryDAO, OrderDAO, MemberDAO, EmployeeDAO, ReportDAO`；
2. **连接**：`db = Database(DbConfig.from_env())`；查询用 `db.read(role)`，写用 `db.transaction(role)`；
3. **登录**：`EmployeeDAO.get_credentials(conn, login_name)` 必须用 `db.auth_read()` 的 conn；密码用 `werkzeug.security.check_password_hash` 校验；成功后把 `employee_id`、`role` 放入 session；
4. **事务**：`create_with_details`、`InventoryDAO.create/adjust`、`MemberDAO.create`、`ProductDAO.create` 等必须由 B 包在 `db.transaction()` 内；
5. **错误**：捕获 `DAOError`，按 `code` 转 HTTP；`message` 可直接展示，`detail` 只进日志；
6. **金额**：DAO 返回 `Decimal`，B 负责 JSON/页面格式化；
7. **分页**：`Page(items, total, page, page_size)`，`page_size` 上限 100；
8. **不要写 SQL、不要用 cursor、不要自己 commit**。

## 9. 遗留问题与 v1.1 建议

| 编号 | 问题 | 建议 |
