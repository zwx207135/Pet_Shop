## 1. 范围与分工

本阶段 B 负责应用侧，在成员A 的 DAO 之上构建 Flask Web 应用：

1. 第7周：Flask 项目骨架、配置、应用工厂、登录鉴权；
2. 第8周：页面层（路由 + 模板 + 前端校验）、业务层（登录/业务规则/事务边界/角色权限）；
3. 第9周：统一异常处理 + 后端日志、角色界面、联调与报告。

A/B 的唯一交接面是 DAO 契约（`docs/第7-9周_DAO接口约定.md`）。B **不写任何 SQL、不直接使用 cursor、不自己 commit**，只调用 DAO 公开接口；事务边界由 B 的业务层用 `db.transaction(role)` 控制。

## 3. 分层架构

```text
页面层 app/routes/ → 业务层 app/services/ → DAO dao/（A） → SQL Server
         │                  │
         └── errors/handlers（统一异常 + 日志）
```

- **页面层**只做：取表单参数、调业务层、把结果或 `DAOError` 交给模板/flash；
- **业务层**做：登录鉴权、参数校验、业务规则、**事务边界**、角色权限；
- **DAO**（A 侧）只接收 `conn` 执行参数化 SQL，不 commit/rollback/close。

## 4. 业务层（services）

| 模块 | 职责 |
|---|---|
| `validation.py` | `parse_int` / `parse_decimal`，非法输入抛 `DAOError(VALIDATION_ERROR)` |
| `auth_service.py` | `login` 用 `db.auth_read()` 取凭据 + `check_password_hash`，成功后写 session |
| `product_service.py` | 建商品 + 初始库存同一事务（`manager`）、改价、停售、列表、类别 |
| `inventory_service.py` | 补货入库（`manager`）、库存/流水查询、预警调整 |
| `order_service.py` | 多商品开单，`db.transaction(当前角色)`，明细由前端合并后转 `OrderItemInput` |
| `member_service.py` | 会员搜索/列表/建档/改资料/积分调整 |
| `employee_service.py` | 员工列表（`db.read("manager")`） |
| `report_service.py` | 商品销售、库存状态、会员消费（`db.read("manager")`） |

关键点：

- 事务边界在 B：`create_product`（商品+库存）、`create_order`（校验→下单→扣库存→写流水）、`adjust_inventory`（入库）都包在 `db.transaction(...)` 里；
- 角色→DB 角色映射：`{"店长": "manager", "店员": "clerk"}`，业务层 `roles_required` 与 DAO 受限账号各校验一次，双重防线；
- 开单的 `employee_id` 取自 `session["employee_id"]`，不允许从表单传（防越权冒名）。

## 5. 页面层（routes）与角色界面

| 路由 | 说明 | 权限 |
|---|---|---|
| `/login` `/logout` | 登录 / 登出 | 公开 |
| `/` | 工作台 + 低库存预警 | 登录 |
| `/products` `/products/new` `/products/<id>/edit` `/products/<id>/status` | 商品查询/新增/编辑/停售 | 查询全员，写操作店长 |
| `/inventory` `/inventory/logs` `/inventory/<id>/adjust` | 库存、流水、补货入库 | 补货店长 |
| `/orders` `/orders/new` `/orders/<id>` `/orders/<id>/status` | 订单查询/开单/详情/改状态 | 登录 |
| `/members` `/members/new` `/members/<id>/edit` `/members/<id>/points` | 会员管理 | 登录 |
| `/employees` | 员工列表 | 店长 |
| `/reports` | 商品销售、库存状态、会员消费 | 店长 |

角色界面：

- **店员**：商品/库存查看、开单、订单查询、会员办理与积分调整；
- **店长**：在店员基础上，新增/编辑/停售商品、补货入库、员工管理、经营报表。

导航栏与按钮按 `roles_required` 的结果做角色条件渲染；同一操作在业务层（装饰器）和数据库层（受限账号）各校验一次。

## 6. 统一异常与日志

- DAO 错误码 → HTTP 状态码映射（`VALIDATION_ERROR→400`、`UNAUTHENTICATED→401`、`FORBIDDEN→403`、`NOT_FOUND→404`、`BUSINESS_RULE_VIOLATION/CONFLICT_*→409`、`DB_UNAVAILABLE/DB_TIMEOUT→503`、`TRANSACTION_FAILED/INTERNAL_ERROR→500`）；
- HTML 页面：`flash_error(error)` 记日志 + `flash(error.message, "danger")` 展示友好文案；
- `Accept: application/json` 的请求返回统一 JSON：

```json
{"ok": false, "code": "BUSINESS_RULE_VIOLATION", "message": "库存不足", "data": null, "request_id": "..."}
```

- 后端日志写入 `logs/app.log`（已 gitignore），每条请求记录 `request_id`、方法、路径、操作名称、用户角色、状态码；出错时额外记录错误码、`message`、`detail`。

## 7. 前端校验

- 开单页用 JS 动态增删商品行，提交前校验：至少一条明细、数量为正整数、商品不重复（重复自动合并）；
- 表单 `required` / `min` / `maxlength` 与业务层 `parse_int`/`parse_decimal` 做二次校验，前端拦截是体验，后端才是可信边界。

## 8. 与 A 的交接面（按 DAO 契约实现）

| 契约条款 | B 侧落实 |
|---|---|
| 入口 `from dao import Database, DbConfig, ...` | `app/extensions.py` 惰性单例 |
| 查询 `db.read(role)`、写 `db.transaction(role)` | 业务层统一调用 |
| 登录用 `db.auth_read()` + `check_password_hash` | `auth_service.login` |
| 事务由 B 控制，DAO 不 commit | `product_service` / `order_service` / `inventory_service` |
| 捕获 `DAOError`，`code` 转 HTTP，`message` 展示、`detail` 进日志 | `errors/handlers.py` |
| `Decimal` 金额由 B 格式化 | 模板过滤器 `money` |
| `Page(items,total,page,page_size)` | 分页宏 `_macros.html` |
| 不写 SQL / 不用 cursor / 不自己 commit | 全局遵守 |
