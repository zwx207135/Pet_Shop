# PetCare 宠物店管理系统 · 操作手册

面向使用者的启动与操作说明。系统采用「页面层（Flask）→ 业务层（services）→ 数据访问层（DAO）→ SQL Server」分层架构，运行于本机 `127.0.0.1:5000`。

---

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11 |
| Python | 3.11+（本机为 Anaconda Python 3.13） |
| 数据库 | SQL Server（本机默认实例 `localhost`，数据库名 `PetCareDB`） |
| ODBC 驱动 | `ODBC Driver 17 for SQL Server`（或 18；如未安装请安装其一） |

---

## 2. 首次安装

### 2.1 安装 Python 依赖

在项目根目录执行：

```bash
pip install -r requirements.txt
```

依赖：`flask`、`werkzeug`、`pyodbc`、`pytest`、`matplotlib`。

### 2.2 初始化数据库

`sql/` 下的脚本需按顺序用 `sqlcmd` 执行。注意**文件编码不同**：

- `01_*` ~ `08_*` 为 **GBK（936）** 编码，用 `-f 936`；
- `migration.sql`、`09_app_accounts.sql`、`regression.sql` 为 **UTF-8 BOM** 编码，用 `-f 65001 -I`。

```bash
sqlcmd -S localhost -E -f 936 -b -i sql/01_create_database.sql
sqlcmd -S localhost -E -f 936 -b -i sql/02_create_tables.sql
sqlcmd -S localhost -E -f 936 -b -i sql/03_insert_data.sql
sqlcmd -S localhost -E -f 936 -b -i sql/06_view.sql
sqlcmd -S localhost -E -f 936 -b -i sql/07_constraint.sql
sqlcmd -S localhost -E -f 936 -b -i sql/08_role.sql
sqlcmd -S localhost -E -f 65001 -I -b -i sql/migration.sql
sqlcmd -S localhost -E -f 65001 -I -b -i sql/09_app_accounts.sql
sqlcmd -S localhost -E -f 65001 -I -b -i sql/regression.sql
```

> `08_role.sql` 执行时会出现若干条 `Msg 229 权限被拒绝` 的**预期演示输出**（验证最小权限生效），属正常现象，不影响后续步骤。

> 说明：`04_crud.sql`、`05_query.sql` 是第 3—4 周的**演示脚本**（仅 INSERT/SELECT，不含 CREATE/ALTER），且 `04` 会重复插入商品 P004，故**初始化阶段跳过**；如需复现第 3—4 周演示可单独执行。

### 2.3 配置数据库连接 `.env`

将 `.env.example` 复制为 `.env`，按 `sql/09_app_accounts.sql` 中的口令填写：

```ini
DB_DRIVER=ODBC Driver 17 for SQL Server
DB_SERVER=localhost
DB_NAME=PetCareDB
DB_AUTH_USER=petcare_auth
DB_AUTH_PASSWORD=PetCare#Auth2026!
DB_CLERK_USER=petcare_clerk
DB_CLERK_PASSWORD=PetCare#Clerk2026!
DB_MANAGER_USER=petcare_manager
DB_MANAGER_PASSWORD=PetCare#Manager2026!
DB_ENCRYPT=yes
DB_TRUST_SERVER_CERTIFICATE=yes
DB_TIMEOUT=5
```

> 若只装了 Driver 18，把 `DB_DRIVER` 改成 `ODBC Driver 18 for SQL Server`。

### 2.4 启动应用

```bash
python run.py
```

浏览器访问 <http://127.0.0.1:5000/login> 即可。

## 3. 登录账号

| 角色 | 登录名 | 密码 | 可见功能 |
| --- | --- | --- | --- |
| 店长 | `manager` | `Manager@123` | 商品、库存（含补货入库）、订单、会员、**员工**、**报表** |
| 店员 | `clerk` | `Clerk@123` | 商品、库存（查看/流水）、订单、会员 |

> 店员访问店长专属页面（如 `/employees`、`/reports`）会被拦截并跳回工作台，给出「没有执行该操作的权限」提示。

## 4. 功能操作指南

### 4.1 工作台（首页 `/`）

- 显示当前用户姓名与角色；
- 右侧「低库存预警」列出库存低于预警值的商品；
- 快捷入口：商品管理 / 库存管理 / 开单 / 订单查询 / 会员管理（店长另有员工管理、经营报表）。

### 4.2 商品管理（`/products`）

- 列表支持**关键字筛选**与**分页**；
- 店长可「新增商品」（自动建立初始库存）、「编辑商品」、切换「在售/停售」状态；
- 停售商品不能继续下单。

### 4.3 库存管理（`/inventory`）

- 列表显示数量、预警值、库存状态（正常 / 库存不足 / 缺货）；
- 「库存流水」（`/inventory/logs`）记录每次入库/销售明细；
- 店长可对商品「补货入库」（`/inventory/<商品编号>/adjust`），入库后库存增加并写入流水。

### 4.4 开单（`/orders/new`）

1. 选择会员（可留空为散客）、支付方式（现金 / 微信 / 支付宝）；
2. 逐行选择商品并填写数量，可「+ 添加商品」增加行；
3. 提交后自动：**相同商品自动合并**、按商品表价格计价、校验库存、扣减库存、写销售流水；
4. 校验失败（参数非法、库存不足、商品停售）会停留在表单页并给出红色提示，**整单回滚**。

### 4.5 订单查询（`/orders`）

- 列表 + 关键字筛选 + 分页；
- 点击进入订单详情（`/orders/<订单号>`）查看金额与明细，可更新订单状态。

### 4.6 会员管理（`/members`）

- 新增会员（姓名、手机号、初始积分）；
- 修改资料、调整积分（正数增加 / 负数扣减）。

### 4.7 经营报表（`/reports`，仅店长）

- 商品销售排行（销量 / 销售额）；
- 库存状态一览；
- 会员消费排行（积分 / 订单数 / 累计消费）。

## 5. 统一错误提示

- 页面层不展示任何 SQL、堆栈、连接串或服务器路径，只显示友好提示；
- 返回 JSON 时结构为 `{"ok", "code", "message", "data", "request_id"}`；
- 详细错误（`detail`）只写入后端日志 `logs/app.log`，日志行含
  `request_id / operation / role / code / message / detail` 字段。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 登录时报「数据库尚未配置」 | 检查 `.env` 是否存在、`DB_DRIVER` 是否与本机安装的 ODBC 驱动一致 |
| 登录账号/密码错误 | 使用上表账号；密码区分大小写 |
| `py` 命令打开应用商店 | 本机 `py` 为 Windows 商店占位符，改用 `python run.py` 或 Anaconda 的 `python.exe` |
| 部分页面空白/报「数据库暂时不可用」 | 确认 SQL Server 服务已启动、`PetCareDB` 已建、`09_app_accounts.sql` 已执行 |
| 截图/联调时中文乱码 | `sql/01~08` 为 GBK 编码，需用 `sqlcmd -f 936` 执行 |
