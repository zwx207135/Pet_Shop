# 数据库实验课程——第一周作业

## 一、项目基本信息

### 1. 项目名称

**PetCare 宠物店管理系统**

### 2. 项目场景

本项目选择**宠物店**作为贯穿整个学期的经营场景。

宠物店主要面向养宠用户提供宠物食品、宠物用品以及基础宠物护理服务，同时提供会员注册、会员积分、商品购买、服务预约等业务。

系统围绕宠物店日常经营过程，对商品、库存、订单、会员、员工以及宠物服务等经营数据进行统一管理，并在后续阶段逐步实现数据库查询、统计分析、事务处理以及数据分析等功能。

### 3. 项目目标

通过建立宠物店经营数据库，将实际经营过程中的业务信息进行结构化管理，实现：

* 商品信息管理
* 商品库存管理
* 会员信息管理
* 商品销售与订单管理
* 订单明细管理
* 会员积分管理
* 宠物服务管理
* 服务预约与消费管理
* 员工及经营角色管理

后续随着课程推进，在当前业务场景基础上逐步完成数据库设计、规范化、应用开发、数据库编程、事务处理以及经营数据分析等任务。

---

# 二、经营角色与职能

根据宠物店的实际经营过程，系统主要涉及以下角色：

| 角色    | 主要职责                               |
| ----- | ---------------------------------- |
| 店长    | 负责门店整体经营、商品与库存管理、员工管理、经营数据查看以及补货管理 |
| 店员    | 负责接待顾客、商品销售、订单处理、会员办理以及宠物服务登记      |
| 会员/顾客 | 购买商品、预约宠物服务、参与会员积分活动               |
| 系统管理员 | 负责系统账号、角色和权限等基础系统信息的维护             |

## 1. 店长

店长负责宠物店的整体经营管理，主要职责包括：

* 管理商品基本信息；
* 查看和管理商品库存；
* 处理商品补货；
* 查看商品销售订单；
* 查看经营统计信息；
* 管理员工相关信息；
* 查看会员信息；
* 管理宠物服务项目。

店长主要负责经营管理和数据查看，不直接承担所有日常销售操作。

---

## 2. 店员

店员是日常经营业务的主要执行者，主要职责包括：

* 接待顾客；
* 查询商品信息和库存；
* 为顾客办理会员；
* 创建商品销售订单；
* 添加和修改订单明细；
* 完成订单结算；
* 记录会员积分；
* 查询宠物服务项目；
* 为顾客登记和处理服务预约；
* 记录服务完成情况。

---

## 3. 会员/顾客

会员或普通顾客是宠物店的主要服务对象，主要参与：

* 浏览和选择商品；
* 购买宠物食品及用品；
* 选择宠物护理服务；
* 预约服务时间；
* 完成消费；
* 获取会员积分；
* 查询自己的消费订单。

普通顾客可以在消费过程中办理会员。

---

## 4. 系统管理员

系统管理员主要负责系统层面的基础管理：

* 管理系统账号；
* 管理角色信息；
* 配置不同角色的系统权限；
* 维护系统基础数据。

系统管理员不直接参与宠物店的日常销售和服务业务。

---

# 三、主要业务流程

## 1. 总体业务流程

宠物店的核心业务可以概括为：

```text
顾客到店
   │
   ↓
是否为会员？
   │
 ┌─┴─────────┐
 ↓           ↓
是           否
 ↓           ↓
查询会员信息  注册会员
 └─────┬─────┘
       ↓
选择商品或宠物服务
       │
 ┌─────┴─────────┐
 ↓               ↓
购买商品         预约服务
 ↓               ↓
查询库存         选择服务项目
 ↓               ↓
创建商品订单     确认预约时间
 ↓               ↓
添加订单明细     创建服务订单
 ↓               ↓
完成支付         完成宠物服务
 ↓               ↓
扣减库存         完成支付
 └───────┬───────┘
         ↓
    记录消费信息
         ↓
    计算会员积分
         ↓
      完成交易
```

该流程覆盖了顾客进入宠物店、选择商品或服务、完成交易以及会员积分等主要经营环节。

---

# 四、商品销售业务流程

商品销售是宠物店最主要的经营业务之一。

具体流程如下：

```text
顾客选择商品
      ↓
店员查询商品信息
      ↓
查询商品库存
      ↓
库存是否充足？
   ↙         ↘
 否           是
 ↓            ↓
提示缺货     创建订单
              ↓
          添加订单明细
              ↓
          计算订单金额
              ↓
          顾客完成支付
              ↓
          扣减商品库存
              ↓
        更新会员消费积分
              ↓
          订单完成
```

例如：

> 顾客来到宠物店购买一袋宠物食品和一个宠物玩具。店员首先查询商品库存，在库存充足的情况下创建订单，并将顾客选择的商品加入订单明细。顾客完成支付后，系统记录订单信息并扣减相应商品库存。如果顾客是会员，则根据本次消费记录会员积分。

---

# 五、宠物服务业务流程

除商品销售外，宠物店还提供基础宠物护理服务，例如宠物洗护、宠物美容和宠物指甲修剪等。

服务业务流程如下：

```text
顾客选择宠物服务
       ↓
查询服务项目
       ↓
选择服务时间
       ↓
店员确认预约
       ↓
创建服务预约
       ↓
顾客到店
       ↓
完成宠物服务
       ↓
完成支付
       ↓
记录服务消费
       ↓
更新会员积分
       ↓
完成服务订单
```

通过该流程，系统可以记录顾客选择的服务项目、预约时间、服务状态以及消费信息。

---

# 六、库存业务流程

商品销售会影响宠物店库存，因此库存管理也是核心经营流程。

基本流程如下：

```text
商品入库
   ↓
增加库存
   ↓
顾客购买商品
   ↓
创建订单
   ↓
订单完成
   ↓
扣减库存
   ↓
检查库存
   ↓
库存是否低于安全库存？
   ↙              ↘
 是                否
 ↓                  ↓
产生补货需求       暂不补货
```

在后续课程中，可以进一步根据商品历史销量和库存情况实现补货分析。

---

# 七、会员业务流程

宠物店设置会员体系，为顾客提供会员积分等功能。

```text
顾客到店
   ↓
是否已有会员？
 ↙          ↘
否           是
↓            ↓
注册会员     查询会员信息
 └──────┬─────┘
        ↓
      消费
        ↓
    完成订单
        ↓
  根据消费记录积分
        ↓
   更新会员积分
```

会员信息主要用于识别顾客、记录消费以及管理积分。

---

# 八、核心经营对象

根据上述业务流程，本项目第一阶段确定以下核心业务对象：

| 业务对象 | 说明                |
| ---- | ----------------- |
| 商品   | 宠物食品、宠物用品等可销售商品   |
| 库存   | 记录商品当前库存及库存变化     |
| 订单   | 记录一次完整的商品或服务消费    |
| 订单明细 | 记录订单中具体购买的商品      |
| 会员   | 记录会员基本信息及会员积分     |
| 员工   | 记录店长、店员等工作人员信息    |
| 宠物服务 | 记录宠物店提供的服务项目      |
| 服务预约 | 记录会员或顾客的服务预约及消费信息 |

这些对象构成后续关系数据库设计的主要业务基础。

# 九、数据边界

## 1. 需要进入数据库的数据

本项目只保存与宠物店经营活动直接相关的数据。

| 数据类别   | 是否进入数据库 | 原因               |
| ------ | ------- | ---------------- |
| 商品基本信息 | 是       | 商品销售和商品管理的基础数据   |
| 商品价格   | 是       | 用于订单金额计算         |
| 商品库存   | 是       | 用于库存管理和后续补货      |
| 库存变化记录 | 是       | 用于追踪商品入库、销售等库存变化 |
| 会员基本信息 | 是       | 用于会员识别和会员管理      |
| 会员积分   | 是       | 支持会员积分业务         |
| 员工基本信息 | 是       | 支持员工管理和后续权限设计    |
| 商品订单   | 是       | 记录商品销售业务         |
| 订单明细   | 是       | 记录订单中具体购买的商品和数量  |
| 宠物服务信息 | 是       | 支持宠物服务业务         |
| 服务预约   | 是       | 管理服务预约和服务消费      |
| 消费金额   | 是       | 用于订单记录和经营统计      |
| 订单状态   | 是       | 用于判断订单是否完成       |

---

## 2. 不进入数据库的数据

以下信息暂时不属于本项目的核心经营数据，因此第一阶段不纳入数据库。

| 数据类别         | 是否进入数据库 | 原因                  |
| ------------ | ------- | ------------------- |
| 顾客与宠物的私人聊天记录 | 否       | 与核心经营业务无直接关系        |
| 店内监控视频       | 否       | 数据规模较大且不属于经营数据库核心业务 |
| 员工之间的聊天记录    | 否       | 与商品销售、库存和订单等核心业务无关  |
| 顾客宠物照片       | 否       | 当前阶段经营业务不依赖该数据      |
| 宠物疾病诊断信息     | 否       | 本项目暂不涉及宠物医疗业务       |
| 商品宣传图片       | 否       | 第一阶段不参与核心业务处理       |
| 顾客的非经营性个人信息  | 否       | 与宠物店核心经营流程无关        |

# 十、数据边界确定原则

本项目的数据边界遵循以下原则：

### 原则 1：服务于核心经营流程

只有参与商品销售、库存管理、订单处理、会员管理和宠物服务等核心业务的数据才进入数据库。

### 原则 2：支持后续数据库操作

进入数据库的数据应能够在后续阶段用于：

* 增删改查；
* 多表连接查询；
* 数据统计；
* 视图；
* 完整性约束；
* 事务处理；
* 经营数据分析。

### 原则 3：避免无关数据

对于与核心经营流程无关的数据，不在当前项目中保存，以避免数据库设计过度复杂。

### 原则 4：为后续分析保留必要数据

商品销量、订单、库存和会员消费等数据不仅服务当前经营业务，也为后续阶段的数据分析和补货决策提供基础。

# 十二、第一周阶段总结

本周确定了数据库实验课程贯穿整个学期的经营场景为**PetCare 宠物店管理系统**。

通过对宠物店实际经营过程进行分析，确定了店长、店员、会员/顾客和系统管理员四类主要角色，并明确了各角色的主要职责。

在业务流程方面，重点梳理了商品销售、库存管理、会员积分以及宠物服务预约等核心流程，明确了从顾客到店、选择商品或服务、完成消费，到更新库存和会员积分的主要业务链路。

在数据边界方面，确定商品、库存、订单、订单明细、会员、员工、宠物服务和服务预约等数据进入数据库，同时排除与核心经营业务无关的数据。

经过本周分析，项目已经完成从现实经营场景到数据库业务需求的初步转换，为后续关系模式设计、数据库建表以及应用开发奠定基础。
